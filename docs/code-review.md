# PingBoard 代码审查标准与流程

> v1.0 · 2026-09-29 · 依据现有代码基线（约 9,300 行：Rust 14 个模块 + 前端 15 个文件）制定。
> 本文档是审查时的**唯一裁决依据**；与本文档冲突的旧习惯，以本文档为准。

---

## 一、审查机制的定位

本项目以单人开发为主，没有 CI 和多评审人环境。因此审查机制设计为三层，按改动风险路由：

| 层级 | 名称 | 时机 | 耗时预算 |
|------|------|------|----------|
| L1 | **提交前自检**（清单 §4.1） | 每次提交前 | ≤10 分钟 |
| L2 | **AI 复审**（本仓库专家「火眼眼」） | 功能完成、合入 main 前 | 每轮给出完整反馈 |
| L3 | **发布前全量走查** | 每次提版本号、打 tag 前 | 按 §4.4 清单逐项过 |

原则：**审查成本与改动风险成正比**。纯样式、文案走快速通道；契约、并发、配置格式变更必须走全量通道。

## 二、审查标准（三级分级）

每条审查意见必须带优先级标记，作者按标记决定改与不改。

### 🔴 阻断（必须修复，否则不得合入）
- **安全**：注入、路径穿越、未校验的外部输入直接进入系统调用或文件读写。
- **数据丢失**：可能损坏用户配置 `config.json` 或事件归档的写法。
- **并发**：竞态、死锁、无条件写共享状态（本项目已有两次此类事故，见 §六）。
- **契约破坏**：18 个 Tauri 命令的签名/命名、事件名 `ping-snapshot`、`Status` 的 serde 行为发生不兼容变更。
- **关键路径无错误处理**：导入、导出、配置读写、停止监控等操作失败时静默吞错。

### 🟡 建议（应当修复，合入前需讨论并记录理由）
- 输入缺校验（目标数量上限、IP 段展开规模、文件大小）。
- 新增行为没有对应测试（前端纯函数已有测试基建 `tests/`，Rust 侧至少对纯函数补 `#[cfg(test)]`）。
- 明显的性能问题：500ms 推送循环内的不必要分配、每帧重建大对象。
- 重复代码达到三次以上，应提取共用函数。

### 💭 细节（可不改，由作者裁量）
- 命名、注释、风格一致性（若无 linter 规则覆盖）。
- 文档缺口、可替代写法说明。

**评审人守则**：一轮审查给出全部反馈，不允许挤牙膏式多轮；每条意见必须说明「为什么」，并给出可操作的改法；好的写法要明确指出（正反馈让标准落地更快）。

## 三、项目专属红线（改动对应代码前必须自查）

以下规则来自本项目真实事故或已验收的设计决策，**逐条都是否决项**：

| # | 红线 | 原因 / 出处 |
|---|------|------------|
| R1 | 新增配置字段**必须**带 serde 默认值；配置枚举**必须**自定义 `deserialize_with` 做未知值降级 | 旧配置整份反序列化失败 → 回落默认值 → **用户全部主机列表丢失**。本项目最贵的教训 |
| R2 | `Status` 序列化为 lowercase（`idle/resolving/ok/timeout/failed`），不得变更大小写形式 | 前后端契约，`src/types.ts` 依赖 |
| R3 | 所有 spawn 子进程必须带 `CREATE_NO_WINDOW (0x0800_0000)` | 否则控制台窗口闪烁 |
| R4 | 禁止 `window.confirm` / `window.alert`；确认交互一律用自绘 `ConfirmDialog` | Tauri WebView 中不可靠 |
| R5 | 所有 hook 必须写在任何条件 `return`（含 `if (!open) return null`）**之前** | 曾因 hook 顺序 → 白屏 React #310 |
| R6 | 「以 props 对象为初值」的本地草稿，不得把该对象放进 effect 依赖（用 `wasOpenRef` 模式） | `ping-snapshot` 每 500ms 重建对象引用 → 草稿被冲掉 |
| R7 | 界面缩放适配：凡 `fixed` + `getBoundingClientRect()` 数值定位的弹出层，定位前必须除以 `currentZoomFactor()` | zoom 下 rect 是视觉坐标，fixed 定位会被再放大一次 |
| R8 | ICMP 探测只能走 Win32 `IcmpSendEcho`；禁止 raw socket / surge-ping | 平台约束与权限模型 |
| R9 | 事件日志：`prev` 记录的是**置 Resolving 之前**的状态；清空必须同时清归档；批次切换用 `session` 而非 `seq` | `MEMORY-EVENTS.md` 三条事故总结 |
| R10 | 并发停止/启动：锁内不 join；worker 退出写 `running=false` 必须是条件写入（`Arc::ptr_eq` 双向堵） | 停止慢事故 + running 竞态事故，见 §六 |
| R11 | 断点样式只加 `max-[1199px]:`；≥1200px 是已验收基线，不得为窄视口改宽视口 | UI 验收基线约定 |
| R12 | 语义色：绿 = 正常、红 = 失败。改徽标/按钮底色的观感前必须先问用户 | 用户明确的产品决策 |
| R13 | Tauri 配置文件按基线管理，改动后须重新记录 md5；打包变体只改 D 盘构建侧并立即还原 | 防止构建配置漂移（见 `MEMORY-RELEASE.md`） |

## 四、审查流程

### 4.1 提交前自检清单（每次提交必过）

```text
□ cargo clippy 无新增 warning（允许基线存量）
□ cargo test 通过（涉及 Rust 逻辑变更时）
□ 前端 npm test 通过（涉及 src/lib、parse 逻辑变更时）
□ §三红线：与本次改动相关的条目逐条确认
□ 契约未变：未改 Tauri 命令签名 / 事件名 / Status 序列化
□ 无调试残留：println!/console.log 大扫除、注释掉的代码块删除
□ UI 变更：1000px 最窄窗口零溢出；含固定定位弹层时验证 125% 缩放
```

### 4.2 分级审查通道

| 通道 | 适用改动 | 流程 |
|------|----------|------|
| **快速通道** | 纯样式、文案、图标、文档 | L1 自检通过即可提交 |
| **标准通道** | 新组件、新命令、配置字段、事件逻辑 | L1 + L2 AI 复审一轮，🟡 以上清零 |
| **全量通道** | R1/R9/R10 相关、契约变更、并发重构、发布 | L1 + L2 多轮至 🔴/🟡 清零 + L3 走查 |

### 4.3 审查轮次规则

1. 单轮审查意见**一次性给全**（禁止 drip-feed）。
2. 作者对每条意见：修复 / 回复理由不改 / 提问澄清，三选一，逐条销项。
3. 复审只验证销项项与新增 diff，不重审未改动代码。
4. 同一 🟡 意见被驳回两次以上 → 升级为 🔴 当面讨论，不在评论区拉锯。

### 4.4 发布前全量走查（提版本号前）

- 对照 `MEMORY-RELEASE.md`：三包构建、digest 校验、ARM64 包流程。
- 大文件走查：`state.rs`、`events.rs` 单文件已超 1200 行，发布前确认无该动的改动漏审。
- QA：100 目标 stop < 300ms；启动/停止/导入/导出/清空事件 全路径手测一遍。
- 配置兼容：用一份 v1.1.0 时代的旧 `config.json` 实测升级不丢数据。

## 五、分语言检查清单

### Rust（src-tauri/src/）

- **错误处理**：`?` 与显式 match 的选择合理；用户可见操作失败必须返回可理解的错误信息，不裸 `unwrap()`（测试代码与确定不变量除外）。
- **并发**：共享状态一律 `Arc<Mutex<_>>` / `AtomicBool`；锁内不做 IO 和 join；退出路径写状态前想一遍「会不会覆盖别人」。
- **序列化**：见 R1/R2；`serde(default)` 与 `deserialize_with` 是配置类型的标配。
- **资源**：`IcmpSendEcho` 句柄、文件句柄在错误分支也正确释放（优先 RAII / drop 语义）。
- **新命令**：在 `commands.rs` 注册、计入 18 个契约清单、前端 `api.ts` 补对应封装。

### TypeScript / React（src/）

- **Hook 纪律**：R5、R6；新增 effect 先问「依赖数组里这个对象是不是每 500ms 变一次」。
- **性能**：`ping-snapshot` 订阅者避免每帧 setState 大对象重组；长列表计算用 `useMemo`。
- **类型**：新接口字段进 `types.ts` 单一来源；禁用 `any` 逃逸（边界处如 `invoke` 返回可用断言并注释原因）。
- **UI 铁律**：R7/R11/R12；单行区域 `whitespace-nowrap shrink-0` + 容器 `overflow-x-auto`；**禁止用缩小字号解决拥挤**。
- **弹层**：容器带 overflow 后，弹出菜单改 `fixed` + `getBoundingClientRect()` 并随 scroll/resize 收起。

### Tauri 配置（src-tauri/）

- `tauri.conf.json` 改动：核对基线 md5，同步记录到新基线（R13）。
- `additionalBrowserArgs` 注意它**完全覆盖** wry 默认参数，不是追加。
- 新依赖进 `Cargo.toml` 时确认许可证与体积影响（本项目交付物对体积敏感）。

## 六、已知反模式速查（本项目实际踩过的坑）

| 反模式 | 后果 | 正确做法 |
|--------|------|----------|
| 配置枚举不带降级反序列化 | 旧配置全废，丢用户数据 | R1 |
| 锁内逐个 `join()` worker | 停止 100 目标要秒级 | 摘句柄 → 全部置 stop → 立即返回，reaper 线程后台 join |
| worker 退出无条件写 `running=false` | 覆盖新 worker 状态，监控状态错乱 | `Arc::ptr_eq` 条件写入，进出双向堵 |
| `useMemo` 写在条件 return 之后 | 白屏（React #310） | R5 |
| effect 依赖整个 `settings` 对象 | 500ms 重置一次用户草稿 | R6 wasOpenRef 模式 |
| fixed 定位直接抄 `getBoundingClientRect()` | 125% 缩放弹出层偏移 | R7 除以 zoom 因子 |
| 用事件 `seq` 区分批次 | 持久化后 seq 归零，新旧事件混批 | 用 `session` |
| 清空事件只清当前表 | 归档没清，「清空了又自己回来」 | 清空 = 当前表 + 归档一起 |

**测试有效性准则**：竞态类修复必须配套一个「回滚到错误写法就失败」的测试——能失败才证明测试有效。

## 附：审查意见书写模板

```text
[🔴/🟡/💭] [分类] 标题（一句话说清是什么问题）
位置：文件:行号
为什么：后果是什么，触发条件是什么
建议：具体改法（给代码片段，不给抽象指令）
```

示例：

```text
🟡 [并发] worker 退出时无条件写 running=false
位置：pinger/mod.rs:142
为什么：旧 worker 的退出写入会覆盖新 worker 刚写的 true，表现为监控状态
       在重启后随机回到「未运行」。
建议：与循环内置 true 一样收敛为条件写入——
     if Arc::ptr_eq(&self.stop, stop) { running.store(false, SeqCst); }
     并补一个「回滚此条件就失败」的回归测试。
```
