# v1.3.0 发布说明 —— 标题栏显示版本号 + 界面细节打磨

> 对比基准：v1.2.1（tag `v1.2.1`）
> 前一版差异见 [`release-notes-1.2.1.md`](release-notes-1.2.1.md)；文件夹设计见 [`folder-design.md`](folder-design.md)

---

## 一、这次解决什么问题

v1.2.1 之后剩下的都是「不影响功能、但天天看得见」的毛病：

1. **看不出正在跑哪个版本。** 用户反馈问题时只能截图标题栏，而标题里没有版本号；
   开发侧也常搞不清用户装的是哪一版，只能靠安装包文件名反推。
2. **分区拖动条太粗、颜色太深。** 常驻一条 6px 宽的灰色色块横在界面中间，
   用户反馈「像一块灰色挡板」；另一批用户则说「太细了不知道能拖」——
   其实两种反馈都对：**视觉太抢眼，而可拖性又不明确**。
3. **详情区左侧出现「两条竖线 + 中间空隙」。** 主表容器自带的右边框与分隔条的 1px 线并排，
   中间还夹着 6px 热区，看上去像两个把手，不像一条边界。

本版把这三件事一起处理，并顺手把导出的两个范围项文案改回与文档一致的口径。

## 二、新增功能

### 2.1 标题栏显示当前版本号

| 场景 | 标题实际内容 |
|---|---|
| 未运行 | `PingBoard — 多主机 Ping 监视器　　　v1.3.0` |
| 运行中 | `PingBoard — 运行中 (4 台)　　　v1.3.0` |
| 版本号尚未取到 / 取值失败 | `PingBoard — 多主机 Ping 监视器`（**不留孤零零的 ` v`**） |

| 项 | 行为 |
|---|---|
| 取值方式 | 运行时 `getVersion()` 读取构建产物的包版本，**不在标题串里写死** |
| 版本源 | `package.json` / `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json` 三处版本字段（提版本时需同步） |
| 间隔 | **三个全角空格**（`U+3000`，各 1em）≈ **3 个汉字宽 ≈ 36px**（12px 标题字，随系统缩放等比变化） |
| 设置入口 | **只在前端 `App.tsx` 的单个 effect 里**，`document.title` 与窗口标题同步写入 |
| 取不到版本时 | 退化为不带版本号的标题，**并 `console.error` 报错**（不静默） |

**为什么间隔不用「几个半角空格」**：Segoe UI 9pt 下一个半角空格仅 ≈ 3px，
两个才 ≈ 6px，不到半个汉字 —— 版本号会和文案糊成一句（观感上是「监视器 v1.3.0」，
而不是结尾的版本标记）。改用 `U+3000` 后宽度恒为 1em，换字体、换缩放都不会跑偏。

> 🩸 **标题只能有一处设置。** 后端 `setup` 里也设过一份标题，实测「设完立刻读是新标题，
> 3 秒后首帧 snapshot 到达又被前端改回不带版本号的」—— 排查这种问题极费时间。
> 现已统一到前端 effect，改文案只改 `src/lib/format.ts` 的 `windowTitle()` 一处。

## 三、界面改善

### 3.1 分隔条：6px 色块 → 1px 细线

| 项 | v1.2.1 | v1.3.0 |
|---|---|---|
| 常驻视觉 | 整条 **6px 实色块**，`slate-300`（深色 `slate-600`） | **1px 细线**，`slate-300`（深色 `slate-600`） |
| 悬停 / 拖动 | 整条变天蓝 | **加粗到 3px** 并染 `sky-500`，100ms 过渡 |
| 布局宽度 | 6px | **6px（未变）** |
| 可拖热区 | 6px | **6px（未变）** |
| 双击 / 键盘 | 恢复默认 / 方向键 8px（Shift 32px） | **未变** |

拆成「6px 热区 + 1px 视觉线」后，**可拖范围和布局一点没动**，只是不再像挡板；
「这里能拖」的提示从「常驻深色」改由「悬停变粗变蓝」承担。

### 3.2 详情区左侧的「双竖线 + 空隙」

主表容器的 `border-r` 与分隔条自身的 1px 线并排，中间还夹着 6px 的透明热区 ——
视觉上形成两条平行线加一道缝。现已移除主表容器的右边框，区域边界统一由分隔条那条线表达
（与侧边栏一侧的既有做法一致）。

## 四、行为变更（轻微）

| 位置 | v1.2.1 | v1.3.0 |
|---|---|---|
| 导出对话框「范围」选项 | 「全部节点」/「仅选中」 | **「选中范围」/「仅勾选行」** |

仅**改文案**，判定逻辑与导出内容完全不变。旧文案一直与「导出范围跟随侧边栏」（v1.1.10 起）
的实际语义不符：名为「全部节点」，实际只导出侧边栏当前范围内的节点。

## 五、兼容性

| 项 | 结论 |
|---|---|
| 配置文件结构 | **无变化**，v1.2.1 配置直接可用 |
| 主机列表 / 文件夹 / 判重口径 | **不受影响** |
| 统计持久化（`pingboard-stats.json`） | **不受影响**，结构未变 |
| 导出格式 | **完全不变**（CSV 仍 15 列，HTML/TXT 字段一致） |
| `localStorage` 键 | **无新增、无变更**（分区宽度键沿用 v1.2.1） |
| 最低系统要求 | **无变化**（Windows 10 + WebView2 Evergreen） |

**升级建议**：直接覆盖安装即可，无需迁移任何数据。

## 八、已知限制

- 标题变长后，**极窄窗口下可能被系统截断**（版本号在末尾，先丢的会是它）。
  窗口标题取决于系统标题栏策略，应用侧不做省略处理。
- 常驻分隔线只有 1px，**浅色主题 + 低对比显示器**上仍然很淡；可拖性依赖悬停时的 3px 天蓝提示。
- ARM64 包自 v1.2.x 起未经真机测试，本版未构建，仍属实验性质。
- 其余限制与 v1.2.1 相同（IPv4 主路径、CSV 未防公式注入、文件夹不支持嵌套等），详见 README「已知限制」。
