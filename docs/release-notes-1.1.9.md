## 二、用户可见的变化

### A. 新功能：报表导出可按结果筛选

工具栏「导出 ▾」新增第 3 组入口「零丢包 / 全部未成功…」，打开「导出报表」对话框。

**v1.1.8 的导出**：只能选「全部 / 仅选中」× 「CSV / TXT / HTML」，**只能整份导出**。
241 台主机里若只有 3 台有问题，你只能导出全部 241 行再自己在 Excel 里筛。

**v1.1.9 的导出**：多一个「筛选口径」维度，可只导出关心的两类节点。

| 口径 | 判定 | 典型用途 |
|---|---|---|
| **零丢包** | `sent > 0` 且 `failed = 0` | 挑出健康线路存档 / 对比基线 |
| **全部未成功** | `sent > 0` 且 `received = 0` | 挑出彻底不通的线路排查（区别于「时好时坏」） |

- 对话框**实时预览命中台数**（如「零丢包 12 台 / 全部未成功 2 台」），点「导出」前就知道会导出几台；0 命中时禁用导出按钮。
- 两种口径**互相独立**、可分别导出；在 `sent > 0` 前提下二者**互斥**，不会重复导出同一台。
- 「范围」（全部 / 仅选中）与「口径」可**叠加**使用。

🩸 **一个容易误解的口径细节**：两种筛选都**要求已实际发过包**（`sent > 0`）。
「未开始探测」或刚点过「清空统计」的主机（`sent = 0`）**不会**被算进「零丢包」——
尽管此时界面上的丢包率显示为 `0.0%`。因为它**根本没发生过任何一次 ping**，「一次没丢包」这个说法对它不成立。
（同理，若只按 `failed == 0` 判定，所有从未启动过的主机会被整体误判成「零丢包」。）

> 完整字段表、判定表与兼容性逐条保证见 `docs/export-filter-design.md`。

### B. 最重要的修复：配置损坏不再「丢光主机列表」

这是 v1.1.9 相对 v1.1.8 **最有价值、也最不容易被察觉**的改动。

**v1.1.8 的隐患**：配置里**任意一个字段**的值类型不对，整份配置反序列化就会失败，
程序回落默认值 → **用户全部主机列表被清空**。而触发门槛极低：

- 手动编辑配置时把 `true` 写成 `"true"`（带引号）
- 某台主机的 `enabled` 被写成 `1`（数字）
- 外部脚本 / 同步工具改写了 JSON 的某个字段
- 配置文件被截断写入（断电、杀进程）

**v1.1.9 的处理**（三条独立防线）：

1. **逐字段默认值 + 16 处字段类型容错**
   单个字段值类型不对时**只降级该字段**，不再牵连整份配置。例：`"enabled": "yes"` → 解析为 `true`；
   某台主机的 `enabled: 1` → `true`；**邻座主机的 `enabled: false` 不会被连带翻转成开启**。
2. **损坏时自动备份 + 尽力抢救**
   真的整份解析失败时（目前只剩「`targets` 数组里混入非对象元素」这一种形态会触发）：
   - 原文件**先完整备份**为 `pingboard-config.corrupt-<时间戳>.json`（内容与原文逐字节一致，可手工恢复）
   - 再从损坏文件里**逐条抢救**仍能读出的主机
   - 抢救 0 台时用**强警告**措辞，并明确提示「**在此之前请勿退出本程序**」
3. **提示真正能被用户看到**（新增第 19 个命令 `take_startup_notice`）
   正式包是 `windows_subsystem = "windows"`（无控制台），原先这类关键信息只能 `eprintln!` → **用户根本看不到**。
   现在改为把提示交给前端弹 toast，且**带完整备份路径 + 抢救台数**、可换行不被省略号截断。

**用户视角的变化**：升级到 v1.1.9 后，即使配置里混进了坏值，也不会再「一启动主机全没了」；
真损坏时会先备份、再明确告诉你抢救回几台、备份在哪。

### C. 其他修复

| 修复 | v1.1.8 的行为 | v1.1.9 的行为 |
|---|---|---|
| **添加主机后落盘失败** | 静默吞错，界面无任何提示（以为添加成功了） | 返回错误并提示 |
| **Delete 键穿透** | 打开「添加主机 / 设置 / 确认框」时按 Delete，会**穿透弹层删掉选中的主机** | 弹层打开时 Delete 不生效；删除选中前**加确认框** |
| **命令漏注册时静默失效** | 前端 `.catch` 吞掉错误，链路断了都没人知道 | 改为 `console.error` 留痕 |
| **提示措辞分级** | 抢救回 0 台（最严重）与抢救回 N 台措辞相同 | 0 台用强警告 + 明确「请勿退出」 |

## 四、兼容性：会不会影响现有使用

### ✅ 配置文件完全向后兼容

v1.1.8 写出的配置文件能被 v1.1.9 正常读取；反之 v1.1.9 写出的也能被 v1.1.8 读取。
**未新增任何配置字段**，不触碰 serde 配置契约（项目红线 R1）。

> ⚠️ 唯一需要**手工留意**的：`tauri.conf.json` 的 `webviewInstallMode` 仍是 `downloadBootstrapper`，
> 与 v1.1.8 一致。内置引导版只在**构建时**临时改，且**不随安装包分发**。

### ✅ 导出格式零变化

CSV 仍固定 **15 列**、HTML 仍 **15 个 `<th>`、TXT 仍每目标 4 行。
筛选**只改变导出的行集合，不改变字段结构** → 既有的 Excel 模板、解析脚本、导入自动化**全部无需改动**。

- 「序号」在筛选后从 1 重新连续编号（因为是全新的一次导出）
- 不筛选时产出的文件与 v1.1.8 **逐字节一致**（已用测试锁定「`All` 时不出现任何筛选标记」）
- 事件日志 CSV（`export_events`，8 列）**完全未改动**

### ✅ 数据文件无变化

事件日志 `events.jsonl` **未新增任何字段**，历史记录可继续读。轮转、清空逻辑未改。

### ✅ 无破坏性契约变更

- 命令数 18 → 19（**纯新增**，无命令被删或改名）
- `export_report` 新增一个**可选**参数 `filter`，缺省即等价于 v1.1.8 行为

### ⚠️ 一处内部基线变更（不影响用户，但影响后续开发）

`src-tauri/tauri.conf.json` 的 **md5 基线随提版本而变**：

| | md5 |
|---|---|
| v1.1.8 时期 | `2c0a8cf0fb8d8f1d5eebea6679c8d270`（**已作废**） |
| v1.1.9 起 | **`4048afd632b3cc649f5904b36727a69e`** |

以后校验「配置文件是否被污染」要用新基线。已写回 `docs/HANDOFF.md` §三与 `MEMORY.md`。

## 五、升级建议

| 场景 | 建议 |
|---|---|
| 正常用户 | 直接覆盖安装。**不需要**任何配置迁移，不会丢数据 |
| 主机很多（100+） | 升级后建议用新增的「零丢包 / 全部未成功」筛选导出一次报表，替代原先「导出全量再在 Excel 里筛」的做法 |
| 之前遇到过「主机列表莫名变空」 | v1.1.9 应已解决该问题。若升级后仍出现，把 `%APPDATA%\com.pingboard.desktop\pingboard-config.corrupt-*.json` 保留好——那是原始配置的完整备份 |

**升级前可选备份**：直接复制 `%APPDATA%\com.pingboard.desktop\pingboard-config.json` 即可（v1.1.9 的自动备份只在「检测到损坏」时才生成）。
