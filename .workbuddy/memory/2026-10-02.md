## 批次 3 提交前拦截：交付包误入 git（881 MB）

`git add -A` 把 `交付包/`（**881 MB / 31 文件**）首次入库，其中三个「完整离线版」各 **217 MB**，
**远超 GitHub 单文件 100 MB 硬上限**，推上去必被拒。

处置：`git reset --mixed HEAD~1` 重做提交（工作区文件一个没丢）→ `.gitignore` 加
`交付包/` + `qa-*.png` → 重新 `add -A` 只剩 11 个源码/文档文件（最大 70 KB）。
`git reflog expire --expire=now --all && git gc --prune=now` 把 `.git` 从 **886 MB 降到 3.9 MB**。
远端核验：139 个树条目 / 115 blob，**零安装包、零 >1MB 文件**。

🩸 新增硬约束：**在仓库根永远不要裸跑 `git add -A`**。要推历史包用 `git add <具体路径>`。

## git 客户端在本环境无法传输 → 改走 GitHub API

`git push` / `git fetch` 全部 `Recv failure: Connection was reset`（`ls-remote` 却正常），
排除了体积、凭据、网络（curl 到 github.com 200）后确认是 git 传输层问题。

兜底脚本 `qa-artifacts/push_via_api.py`（不入库）：读远端 tree → 与本地 `ls-tree -r` 逐 blob
比对 → 只推差异文件（`POST /git/blobs` + `/git/trees` base_tree + `/git/commits` + `PATCH /git/refs`）。
**自带复核**：推完再比一次，剩余差异必须为空才报成功。

⚠️ 凭据文件是 URL 形式（`https://user:gho_XXX@github.com`），token 后还粘着密码字段 ——
**必须用正则 `gho_[A-Za-z0-9]+` 提取**，按空白切分会取错。

### 端到端 QA 的五个坑（下次直接照抄）

1. **debug exe 必须配 `npm run dev`** —— debug 走 `devUrl=localhost:1420`，
   只 `cargo build` 启动会白屏「localhost 拒绝连接」。
2. **后台进程用 `run_in_background`，`cmd &` 会在工具返回时被杀**。
3. **坐标点击不准**（`ui_scale` + DPI 缩放，点了三次都落到列头）→ 改用 CDP：
   `additionalBrowserArgs` 加 `--remote-debugging-port=9333`（**完全覆盖** wry 默认参数），
   `GET /json/list` 取 ws URL，`Runtime.evaluate` 读 DOM，还能
   `window.__TAURI_INTERNALS__.invoke('get_state')` **直问后端**，比截图可靠得多。
4. **「未开始」徽标是 `Status`（探测状态 idle），与 `enabled` 无关** —— v1.1.2 起表格无 `enabled` 列，
   判断 `enabled` 必须调 `get_state`。
5. **Tauri 命令参数是扁平的**：`update_target` 收 `{id, name, host, enabled}`，**不是 patch 对象**。

改 `tauri.conf.json` 测完**必须还原并核对 md5** —— `json.dump` 会重排格式，md5 必变。
