### 🩸 新教训一：emoji 图标无法用 CSS 控色
`🔍`（U+1F50D）由 **Segoe UI Emoji 彩色字形**渲染，`text-*` 对它**完全无效** —— 「把 emoji 的 class 改深一档」
根本不会生效。要控色/控粗细**必须自绘 SVG + `stroke="currentColor"`**（`✕` 早先已因此改成自绘）。
顺带把容器从 `absolute left-2 top-1` 改为 `absolute inset-y-0 left-2 flex items-center pointer-events-none`：
垂直居中不再依赖字体行高，且**修掉了原 span 遮挡输入框左缘点击**的隐藏问题。

### 🩸 新教训二：CDP 验证时「已有实例在跑」会让第二个实例复用浏览器进程
`connectCDP` 一直抛 `NO_CDP_PAGE`（白等 90 s 超时）。根因：**用户手动打开的 PingBoard 已启动 WebView2
浏览器进程**，我的验证实例复用了它 —— 而那个进程没带 `--remote-debugging-port`，端口上的 `/json/list` 永远为空。
- 诊断手法：查目标进程的**父进程名** —— `explorer.exe` 说明是**用户手动开的（绝不能杀）**，shell/node 才是自己残留。
- 修法：给验证实例设 `WEBVIEW2_USER_DATA_FOLDER`（独立目录）→ 独立浏览器进程，调试端口生效；
  同时把应用自身的 `additionalBrowserArgs`（含本机必需的 `--in-process-gpu`）原样抄进环境变量。
- 已补进技能 `tauri2-windows-package-and-verify` §五。

### 🩸 新教训三：浮层图标的背景色不能用「向上遍历」算

## 3. macOS / Windows ARM64 可行性评估（只调研，未动手）
- **macOS：不可交叉编译** —— 官方明确 `.app` / `.dmg` **只能在 macOS 上创建**，另需 Xcode。
  **代码必须改**（不是「能跑但要测」，是**直接编译失败**）：`icmp.rs` 全盘 `use windows::*` 且无门控
  （`IcmpSendEcho` 是 Windows IP Helper 独有）→ 须换 `SOCK_DGRAM`+`IPPROTO_ICMP` 或 spawn `/sbin/ping`；
  `ping.exe` → `/sbin/ping` 且**参数语义不同**（Win `-n 1 -w <ms>` vs macOS `-c 1 -W <ms>`）；
  `windows` 依赖须移进 `[target.'cfg(windows)'.dependencies]`。
  分发还要 **Apple 开发者账号（99 USD/年）** 做 codesign + notarize，否则 Gatekeeper 拦截。
  → 结论：**是一个平台适配项目，不是「加个 target 打个包」**。
- **Windows ARM64：技术可行，但验证受限** —— VS2022 装「MSVC v143 - VS 2022 C++ ARM64 生成工具」
  + `rustup target add aarch64-pc-windows-msvc` + `tauri build --target aarch64-pc-windows-msvc --bundles nsis`；

  ⚠️ 只有 NSIS 支持 ARM64（MSI/WiX 不支持）；**安装程序本身仍是 x86**（ARM 机器上靠模拟运行），
  **被安装的应用才是原生 ARM64** —— 别看到 setup.exe 是 x86 就以为打错了。
  🩸 **最大限制：x64 机器无法运行 ARM64 程序**（反向才行）→ 只能验证「编译通过 + 产物 PE 头为 ARM64」，
  **无法真机冒烟**；GitHub Actions 也没有 ARM64 Windows runner（需自托管）。
  → 收益判断：ARM64 Windows 设备占比小，且 **x64 包在 ARM 设备上可通过模拟正常运行**。
