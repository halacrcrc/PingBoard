## 关键技术决策（下次改这个项目务必先看）

1. **ICMP 实现走 Win32 IP Helper `IcmpSendEcho`**（`windows` crate 0.61），每个工作线程复用一个 `IcmpCreateFile` 句柄。
   **绝不能用 raw socket / surge-ping** —— 那些需要管理员权限。本方案普通用户权限即可。
2. **降级路径**：`IcmpCreateFile` 失败时改用系统 `ping.exe`，且**必须**带
   `creation_flags(0x0800_0000 /* CREATE_NO_WINDOW */)`，否则闪黑框。
3. **数据流**：后端每 500ms 主动 emit 一次聚合事件 `ping-snapshot`，前端整体替换状态。
   **不要让前端处理每次探测事件**（100 主机 × 1Hz 会把 WebView 拖垮）。
4. **统计口径**：`loss_pct = failed/sent*100`（sent=0 时为 0）；`avg = Σrtt/成功次数`；
   history 环形缓冲保留最近 60 条（失败记 None）。
5. **⚠️ 最重要的坑 —— WebView2 GPU 崩溃导致空窗口**：
   本机（AMD RX 9070 GRE + 向日葵 OrayIddDriver 虚拟显示器）上**每次启动必现**：
   独立 GPU 进程崩溃（`gpu_data_manager_impl_private.cc:436: GPU process isn't usable. Goodbye.`，
   `LOG_FATAL`）→ 整个 WebView2 被拖垮 → 宿主窗口内容区全黑。
   **`--disable-gpu` 无法修复**（它不移除独立 GPU 进程）。
   **真正有效的修复是 `--in-process-gpu`**，写在 `src-tauri/tauri.conf.json` 的
   `app.windows[0].additionalBrowserArgs`：
   `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --in-process-gpu --disable-gpu --disable-gpu-compositing --disable-direct-composition`
   注意：该字段会**完全覆盖** Tauri/wry 自带默认参数，所以必须手动把默认 features 串补回。

## 本机环境坑（复现构建时必看）

- **cargo / tauri / Node 连本地回环都要绕沙箱代理**：前置 `NO_PROXY='*' no_proxy='*'`，
  否则 cargo 出网被 `127.0.0.1:10164` 阻断。
- npm 官方源可能卡住，改用 `--registry=https://registry.npmmirror.com`。
- WorkBuddy safe-delete 守护会拦 Vite `emptyOutDir`（一次删 >50 文件）：
  重新构建前先用 PowerShell `Remove-Item -Recurse -Force D:/pinginfo/dist`。
- `indexmap 1.x` 的 `build.rs` 用 autocfg 探测 std，在 rustc 1.98 下探测失败 →
  已在 `Cargo.toml` 显式启用 indexmap 的 `std` 特性绕过（见其文件内中文注释）。
- **验证 WebView2 界面是否真的渲染**：`PrintWindow` 抓不到 WebView2 合成层（恒黑），
  屏幕截图又因窗口无法置前而不可靠。**正解是用 CDP**：
  Tauri 2 会忽略 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 环境变量，
  必须通过 `tauri.conf.json` 的 `additionalBrowserArgs` 注入 `--remote-debugging-port=9222`，
  再用 Node 22 自带的全局 `WebSocket` 连 `http://127.0.0.1:9222/json/list` 读 DOM +
  `Page.captureScreenshot`。**验证完必须把调试端口从配置里移除再出正式包。**
