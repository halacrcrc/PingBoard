# 2026-09-21 · PingBoard v1.1.0 增量开发与发版

## 本轮需求（用户提出 5 项）
1. 支持 txt 文本与 **Excel** 文件导入
2. 一键清空列表 + 选择部分 IP 清除；清除交互与「启用」一致（复选框、支持全选）
3. `README.md` 里删掉「功能对标 NirSoft PingInfoView」
4. 并发线程上限**增加开关**，并说明性能影响
5. 选中列表内的 IP 后，可单独开始 / 结束 ping

## 技术方案（主理人定的设计决策）
- **导入走「前端选路径 → 后端读文件」**，与现有导出（`dialog.save()` + `export_report`）对称。
  新增命令 `read_import_file(path) -> ImportPayload`：
  `{kind:"text",text}` 或 `{kind:"table",rows}`
  - txt：BOM → 严格 UTF-8 → **GBK**（`encoding_rs`）→ lossy 四级探测
  - Excel：`calamine` 读第一个工作表
  - **解析仍在复用前端 `parseBatch`/`expandIpRange`**，避免 IP 段展开逻辑写成两份
- 新增前端依赖 **0 个**；Rust 新增 `calamine 0.26.1` + `encoding_rs 0.8.41`
- 「选择」复选框列**复用现有 `selected` 集合**，不引入第二套选择状态
- 清空/删除用**自建 `ConfirmDialog`**（`window.confirm` 在 Tauri WebView 下不可靠）
- `PingSettings.limit_max_threads`（默认 true，`#[serde(default="default_true")]` 保证
  **旧配置无损升级**）；关闭后不拦截但保留 **4096 硬保护**
- 版本号 1.0.0 → **1.1.0**；安装包 1.67 MB → **2.03 MB**（后端 Excel 解析库的代价）

## 严重缺陷：两轮 QA 各抓到一个
### ① P0 白屏（QA 首轮抓到，release blocker）
`AddTargetsDialog.tsx` 的 `useMemo` 写在 `if (!open) return null;` **之后** →
组件关闭时 11 个 hook、打开时 12 个 → React 抛
`Rendered more hooks than during the previous render`（生产包 = **Minified React error #310**）
→ 无 ErrorBoundary，**卸载整个根 → 全屏白屏**。
「添加主机」是唯一的新增入口，等于三个 tab 全废。
修复：hook 前移到早退之前（`useMemo` 现位于 158-162 行，早退在 164 行）。
**教训：React 组件的所有 hook 必须在任何条件 return 之前无条件调用。**

加了「选择」列后表格总宽增加，「启用」被挤成竖排、「延迟(ms)」「成功/失败」折成两行。

（窗口过窄改为横向滚动而非压缩列宽）。修后 14 个表头 clientHeight 全为 30px、无横向滚动条。

## 平台与依赖审计（用户提问「最低支持什么平台 / 装完还要哪些组件」）
用 Python 解析 `pingboard.exe` 的 PE 头与导入表，逐一验证：
- **架构：仅 x64**（安装包名带 x64）。未构建 ARM64 原生版；32 位系统装不了。
- PE 头 `MinOSVersion 6.0` 只是链接器默认值，**不代表真实要求**。
- 导入的 22 个 DLL **全部是系统 DLL**：kernel32 / user32 / gdi32 / **iphlpapi** / ws2_32 / ole32 /
  oleaut32 / advapi32 / dwmapi / comctl32 / shell32 / shlwapi / ntdll / bcryptprimitives
  + `api-ms-win-crt-*`（UCRT）。据此得到三个关键结论：
  - **无 `vcruntime140.dll` / `msvcp140.dll` → 不需要 VC++ 运行库**（Rust 静态链接 CRT）
  - `api-ms-win-crt-*` 在 Win10+ 属系统自带 UCRT → **不需要装任何补丁/可再发行包**
  - **无 `WebView2Loader.dll` 导入 → wry 把 loader 静态链进 exe，不需要随包分发该 DLL**
  - 也不需要 .NET Framework（纯 Win32 原生）
- **真实最低平台：Windows 10**（WebView2 官方支持 Windows 10 SAC 1709+ / Server 2016+）；
  **Win7 / 8.1 不支持**——WebView2 Runtime 自 109 版起已停止支持这两个系统。
- **唯一外部运行时依赖 = WebView2 Evergreen Runtime**。`tauri.conf.json` 用的是
  `downloadBootstrapper` → **目标机缺失时，安装过程需要联网**（已在本地
  `tauri-utils-2.9.3/src/config.rs` 源码里确认注释 "Requires an internet connection"）。
  要离线部署得改成 `embedBootstrapper`（安装包 +≈1.8 MB）或 `offlineInstaller`（+≈127 MB）。
- 后端 `pinger/icmp.rs` **没有 `cfg(windows)` 门控**（只有 `fallback.rs` 有 3 处），
  `windows` crate 是无条件依赖 → **当前代码库不能跨平台编译**，Linux/macOS 需先做条件编译拆分。
- 本机实测环境：WebView2 Runtime `153.0.4234.48`
  （`C:\Program Files (x86)\Microsoft\EdgeWebView\Application\`），宿主 `10.0.26200`（Win11）。
- 磁盘占用（实测）：程序 `%LOCALAPPDATA%\PingBoard` = **5.5 MB**（exe + uninstall.exe）；
  WebView2 用户数据 `%LOCALAPPDATA%\com.pingboard.desktop\EBWebView` = **9.7 MB**（随缓存增长）；
  配置 `%APPDATA%\com.pingboard.desktop\pingboard-config.json` = 549 B。
- 运维提示：本会话 **`PowerShell` 工具无任何 stdout 返回**（连 `Write-Output` 都空），
  注册表查询改为直接读文件系统（`/c/Program Files (x86)/Microsoft/EdgeWebView/...`）。

### 产出（新增两个安装包，均 x64 / NSIS / currentUser）
| 变体 | webviewInstallMode | 体积 | 内嵌的 WebView2 载荷 |
|---|---|---|---|
| 在线引导版（原有） | `downloadBootstrapper` | 2,027,088 B | 无（多一个 `NSISdl.dll` 插件） |
| 内置引导版 | `embedBootstrapper` | 3,765,441 B | `$TEMP\MicrosoftEdgeWebview2Setup.exe` 1,844,944 B |
| 完整离线版 | `offlineInstaller` | 217,845,983 B | `$TEMP\MicrosoftEdgeWebView2RuntimeInstaller.exe` 213,053,648 B |

- 构建各耗时 ≈2 分钟（embed）/ ≈3 分钟（offline）；`offlineInstaller` 会先从
  `https://go.microsoft.com/fwlink/?linkid=2124701` 下载 203 MiB 离线运行时（**实测该 URL 可达，
  返回 Content-Length 213,053,648，与本包内嵌字节数完全一致**）
- 三个包解包后 `uninstall.exe` **完全相同**；`pingboard.exe` 仅差 **25 字节**，已逐字节定位：
  - 22 字节 = 构建元数据（PE `TimeDateStamp`、调试目录里重复的时间戳、CodeView `RSDS` GUID）
  - 1 字节 = `.text` 中 `mov rax, imm64` 立即数最低位，取值 **1/2/3 与 webviewInstallMode 一一对应**
    （v1.0.0 与在线版同为 1）→ 可判定为编译期写入的安装模式判别值，即三包唯一的**预期**差异
- Tauri 打包时会解析二进制里的 `TYPE_VAR_UNK` 占位串并改成 `TYPE_VAR_NSS`（NSIS），
  且**打包后会把磁盘上的 exe 还原**（所以 `target/release/pingboard.exe` 里读到的仍是 `TYPE_VAR_UNK`，
  只有包内那份是 `NSS`）—— 别再拿磁盘 exe 和包内 exe 直接比哈希，会误判。
- 内嵌的 WebView2 安装程序**均为微软官方文件**：`Get-AuthenticodeSignature` → `Status=Valid`、
  签署者 `CN=Microsoft Corporation`；版本分别为 1.3.271.7（引导）/ 1.3.269.9（离线）。
  安装包自身 `ProductName=PingBoard` / `FileVersion=1.1.0` / `NotSigned`（本项目未做代码签名，正常）。

### 未做本机实装测试（有意决策，非遗漏）
本机 WebView2 已安装 → 三种包的安装脚本都会**跳过 WebView2 安装段**，
实装根本触发不到新增代码路径，却会覆写用户既有安装的桌面/开始菜单快捷方式与卸载注册表项

载荷逐字节比对、微软签名验签。端到端实装建议在干净虚拟机做。
**核验：用户既有安装 `pingboard.exe` SHA-256 = `f4c6c65b…3fd76363`，与之前记录一致，全程未被触碰。**
